## Harte Vorgaben
- **Semantische Basis `<details>/<summary>`** statt Button+JS (Masterplan-Vorgabe). Ohne JS: Antworten sind erreichbar/aufklappbar (native), nichts ist per `display:none` dauerhaft versteckt. Server rendert das erste Item `open` (wie im Mock), die übrigen geschlossen – alle Inhalte stehen im DOM (SEO/No-JS).
- **Optik 1:1** aus `.faqq/.faqa/.pm`: Frage in Archivo 700/17.5 px navy, Plus/Minus-Marker 16 px aus zwei Strichen; im geöffneten Zustand wird der vertikale Strich ausgeblendet (`details[open] .pm::after{transform:scaleY(0)}`). Native `summary`-Marker (Dreieck) entfernen (`summary::-webkit-details-marker{display:none}` + `list-style:none`).
- **Marker per CSS über `[open]`** – kein JS nötig. „JS nur für Styling" heißt: falls überhaupt, nur dezente Höhen-/Icon-Transition; **kein** erzwungenes Single-Open-Akkordeon (der Mock erzwingt es auch nicht). Reduced-Motion respektieren.
- **A11y:** `<summary>` liefert den Aufklapp-Zustand nativ (kein manuelles `aria-expanded` nötig); Plus/Minus-Marker `aria-hidden`. Fokusring sichtbar. Frage als klickbare `summary`, Antwort im `<details>`-Body.
- **Keine Fred-Fließtexte:** Für die Demo auf `/_bausteine` **neutrale** Beispiel-Fragen/Antworten verwenden (kein Pakete-FAQ-Wortlaut). Die echten Pakete-FAQ-Texte kommen auf `/pakete` (Phase 2.1) bzw. aus Sanity (Phase 3.6).
- **Tokens `--gn-*`**, Mock-CSS als co-lokiertes Modul, literale Werte kommentiert.
